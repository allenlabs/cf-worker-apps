Bash에서 실행하는 예시입니다. 수집 토큰을 입력하면 my-worker / collector.connected 이벤트 한 건을 전송합니다. 조회 필터를 비우고 최근 5분을 선택하면 확인할 수 있습니다.


        
2. Cloudflare Workers 연결
배포된 Tail 수집기 cf-observe-tail에 producer Worker를 연결하면 호출 종료 후 console 로그·예외·실행 결과를 받습니다. 기존 tail_consumers가 있으면 유지하면서 항목을 추가하세요. CF Observe와 Tail 수집기 자신은 연결하지 않습니다. 자세한 절차는 저장소의 apps/cf-observe/collectors/README.md에 있습니다.
실행 중인 작업 진행 상황은 같은 계정의 Service Binding으로 직접 전송할 수 있습니다. 저장소의 apps/cf-observe/src/collectors/publisher.js에서 publishEvents를 가져오세요. 아래 설정과 호출을 producer Worker에 적용하고, export마다 고유하고 재시도 동안 동일한 idempotencyKey를 지정하세요.
producer Worker에서 npx wrangler secret put OBSERVE_INGEST_TOKEN으로 수집 토큰을 등록한 뒤, 요청 처리 코드에서 아래 함수를 호출합니다.
실행 중인 작업의 진행 상황은 직접 전송하세요. Tail은 호출 종료 후 전달합니다. waitUntil만으로 중요한 업무 이벤트의 전달이 보장되지는 않으며, 그런 이벤트에는 소스의 영속 outbox가 필요합니다.

        
3. 기존 OTLP SDK·Collector 연결
서버·컨테이너 수집기는 별도로 설치·연결해야 합니다. 기존 Collector가 있다면 저장소의 apps/cf-observe/examples/otel-collector.yaml을 참고하고, 설치한 Collector 버전으로 설정을 검사하세요. 이 예시는 OTLP 전달만 설정하며, 파일 로그 수집과 디스크 전송 대기열은 포함하지 않습니다.
앱 SDK는 같은 호스트의 OTLP 수신기로 보낼 수 있습니다. 예시의 대기열은 메모리 기반이므로 재시작을 견뎌야 한다면 Collector의 디스크 저장을 별도로 설정해야 합니다. 메트릭의 수집 주기는 로그 전송 지연과 별개입니다.

        
민감한 본문·속성은 수집 단계에서 제거하세요. 이벤트 상세와 JSON 내보내기는 수집 시 필터링·가림 처리를 적용한 저장 데이터를 표시합니다.
