# One subscription authorization

The account panel starts one official Codex device authorization. An administrator confirms the selected account's usage rights, opens the official device page, approves the code, and clicks **Check login**. Under the default `auto` policy, the resulting standard Codex profile supplies both Pi inference and the image tool. In SIWC-only mode, this device connection supplies the image tool while ordinary inference continues to require the retained SIWC grant. There is no second image connection control, automatic login, local Codex process, API-key fallback, or paid API endpoint.

The existing Sign in with ChatGPT (SIWC) connection keeps working while a replacement device login is pending or fails. With the default inference policy, a successful unified authorization selects the installed Pi `openai-codex` provider for new operations. An installation can require retained SIWC grants for all ordinary inference with `SUBSCRIPTION_INFERENCE_PROVIDER=siwc`. Manual requests also persist only a request hash and admission metadata in the Durable Object, allowing a replay across authorization changes. Pre-migration requests use the native request-ID lookup and completed answer model. An unfinished pre-migration submission has no captured model field; it keeps its sole supported SIWC provider with the current selected model ID, without scanning history. Already admitted operations retain their persisted provider. Completed results replay from storage; unfinished native operations are denied when the installation requires SIWC. Existing conversation model IDs, thinking levels, account assignment and context remain; an ID absent from the selected provider fails with `subscription_model_unavailable`.

## Ordinary inference policy

`SUBSCRIPTION_INFERENCE_PROVIDER` accepts `auto` (default when absent) or `siwc`. Every other value, including an explicit empty string, fails before credential reads. `auto` keeps the existing unified-Codex selection. `siwc` selects the retained legacy grant for every account and requires both `resource.invoke` and `chatgpt.tokens.use.direct`; an account without that grant is unavailable. There is no native fallback, new authorization flow or automatic resubmission.

Account status, model availability, verified identity, plan, expiry and information refresh follow the selected inference grant. Native image status and access retain their existing Codex profile. An account can therefore have connected native images while SIWC inference is unavailable. `codexInferenceReady` and `siwcInferenceReady` report the independent grants for the separately configured inference bridge.

New ordinary and GitHub authoring operations snapshot SIWC in `siwc` mode. Existing provider, account, model and session snapshots stay unchanged. Completed operations replay their cached results without a provider call. Unfinished native snapshots are rejected with `subscription_inference_provider_disabled` before native credential access or fetch; failed operations remain historical. Switching policy does not rewrite or retry them. An explicitly configured native bridge retains its independent provider choice, and native images continue to work.

## Credentials and identity

The existing Credentials Durable Object, AES-GCM wrapping configuration and `codexImageProfile` storage key are retained. Profiles created by the old image-only flow are not promoted to inference. A new protected account connection records an explicit administrator migration intent and the current legacy registration fingerprint inside its sealed pending attempt. The fingerprint is checked before completing the authorization and before profile access. A failed or ambiguous refresh requires reconnection and does not select SIWC as a fallback.

SIWC subject IDs belong to their issuer/client combination. Migration does not compare subjects from different clients. The new grant verifies issuer, audience, signed subject, configured email and any existing verified workspace/account pin. A same-client subject remains pinned. After migration, legacy image-only start/disconnect routes reject the account even when its bearer has been disconnected. An independent encrypted `codexRegistration` retains the standard Codex subject/client/account pin even after disconnect. A transaction installs the first profile and registration together; reconnection and refresh preserve that identity. The access token's account claim must match the signed ID-token account before inference or image dispatch. Email alone does not establish migration ownership: the protected Super Admin action, sealed migration intent and retained registration are required.

Unified native inference uses `https://chatgpt.com/backend-api/codex/responses`; images use `https://chatgpt.com/backend-api/codex/images/generations`. Both share one refresh flight and standard Codex profile. The installed provider's `stream` and `streamSimple` use SSE on Workers. Legacy SIWC inference continues using `https://api.openai.com/v1/responses`; its bearer is never given to the Codex backend. The `directUsageGranted` status field remains an authentic SIWC scope fact; account allocation uses `inferenceReady`.

An already pending SIWC callback can still finish through the explicitly labeled legacy form. The default account connection route starts the unified device flow. A confirmed account disconnect clears both grants and pending attempts while retaining the identity policy, verified legacy registration and usage history.

## Verification boundary

The native workerd check uses SQLite Durable Objects, real fixture RS256/JWKS verification, the installed Pi Codex provider and mocked outbound provider endpoints. It exercises one device grant, encrypted restart, public inference during pending/failed replacement, old operation transport pins, provider migration with preserved history, the production image request, shared refresh, workspace mismatch and protected SSO/CSRF routes. UI checks prove one connection control and no automatic polling. Existing SIWC and GitHub authoring checks cover the retained public provider and authoring snapshots.

A real account's future device authorization and hosted inference/image entitlement still require live verification. These Codex endpoints follow the official client implementation rather than a separately versioned third-party API guarantee.
