# ChatGPT subscription connections

This private Worker exposes the Korean connection page at `/gatekeeper/subscription`. Bind it to the existing OS router as `GATEKEEPER_SUBSCRIPTION`. The native router already forwards that path. Set `PUBLIC_ORIGIN` to the OS origin. With `SUBSCRIPTION_AUTH_MODE` omitted or set to `access`, protect the whole origin with the same Cloudflare Access application. This Worker separately verifies the Access JWT's signature, issuer, audience, expiry and its own pinned administrator email. It has no public route or inference HTTP endpoint.

Deploy it under a new Worker name with a new `Credentials` namespace. It re-exports the public Cloud Agent `Credentials` and `CloudAgentInference` implementations. The only DO binding and migration are `Credentials`. It never creates an Assistant, PiHarness or another agent loop. The imports include shared runtime dependencies; the selected connection methods only pin `TENANT_ID` and use DO storage. No D1, Channel Talk, SSO or GitHub binding is required.

The protected page lists named subscription connections and their readiness. Add a connection with a display name, then choose the OpenAI account during SIWC or device login. Labels must be nonempty, at most 128 UTF-8 bytes, and contain no control characters. Each named connection uses an existing `account-<uuid>` Credentials object with its own grants, pending attempts, identity pins, protocol choice and encrypted account-information cache. Selecting a row edits that connection only. It does not select a global inference account, change Channel Talk's default or add load balancing. The legacy `owner` connection and its stored grants remain available.

The owner catalog reuses `adminAccounts`, includes `owner` plus only rows marked `subscriptionSetup: true`, and permits at most 20 total inventory rows, including unrelated legacy rows. Legacy administrator account creation keeps its required email policy and is not added to this catalog automatically. The protected page can permanently delete a selected named setup connection after confirmation. The owner and unrelated administrator accounts cannot be deleted here. There is no reset, account replacement or cross-account fallback. Use `#connection=account-<uuid>` to open a known connection or `#add` to focus its add form. Switching clears the callback, authorization link, device code, identity and usage, cancels polling, and ignores late responses from the previous selection.

The authenticated same-origin `POST /connections` returns `{connections}` and `POST /connections/create` accepts only `{label}`, returning `{id, connections}`. These paths are relative to `/gatekeeper/subscription`. Catalog rows contain only `{id, label, provider, ready}`. Existing operations accept optional `accountId` alongside their existing fields. Omission retains the legacy owner behavior. A supplied ID must belong to this catalog before the Worker opens its Credentials object. Authentication and exact request validation precede account access. Catalog listing reads local status without querying usage for every connection.

The native OS Admin Providers panel uses these same protected endpoints for subscription settings.
`POST /connections/delete` accepts only `{accountId, confirmed: true}` and returns `{connections}` with only the surviving IDs and labels. The response does not query sibling status after deletion. It disconnects both protocols, cancels pending attempts, removes the named catalog row and its saved identity, registration pins and encrypted quota cache/history. It rejects owner, unknown and general administrator accounts. A Channel Talk default, pool or observed-thread reference blocks deletion without changing routing. Busy OAuth work keeps the row. The owner serializes reference checks, disconnect and catalog removal with its native Durable Object concurrency gate. Routing writers recheck the current inventory in their commit transaction, so an earlier readiness check cannot restore a deleted account reference. These writes span two objects: an interrupted deletion can leave a disconnected catalog row for a later explicit retry. A stored deletion marker rejects late login starts already resolved to the removed object. Deletion cannot cancel inference requests that already obtained a provider token or revoke provider-side authorization.

`POST /connections/rename` accepts `{accountId, label}` and returns `{connections}`. It changes only
the catalog label, including the default owner, preserving the stable ID, grants, identity pins,
creation time, and saved usage. Organization model display names remain separate OS admin settings.

`POST /overview` accepts `{}` and returns `{connections}` with protected identity, last successful
snapshot, last attempt, and recorded quota history. It reads local state without querying OpenAI.
One unavailable account does not prevent other rows from loading. This richer response is never
exposed through the inference binding's ordinary model catalog. Explicit `/account-info` refreshes
retain the existing 60-second encrypted cache and in-flight request deduplication.
Successful observations retain at most 168 hourly samples from the last seven days, with a bounded
encrypted storage record. Cache hits do not add history. Lookup failures preserve the last successful
snapshot, while a different protocol, client, subject, or account cannot inherit that snapshot.
Optional model-specific limits appear only when supplied; each reset belongs to its own window.

The page asks for explicit subscription usage approval and calls `Credentials.start(true, "connect")`. The user selects an account and workspace at OpenAI without typing an email in the OS. A fresh namespace starts with `dynamic_agent_client`. Only an explicit setup intent can create a registration with `identitySelection: "oauth"`; its normalized email comes from a signature-, issuer-, audience-, expiry- and nonce-verified ID token. A pre-login email policy is neither enforced nor overwritten when no verified registration exists. Existing legacy registrations keep their email policy, and `start(true)` and Codex/image callers retain their strict behavior.

The official flow expects a local callback listener. This page uses the repository-tested manual adaptation: the user copies the full `http://127.0.0.1:1455/auth/callback?...` address into the page's form. Never ask for that address in chat. The form submits it only in a bounded same-origin JSON POST body and clears the field immediately. It does not navigate to, log or persist the callback URL in browser storage.

Readiness comes from `status.inferenceReady` for the selected protocol, with separate `siwcInferenceReady` and `codexInferenceReady` values. The protected page displays verified name, email, plan, supplied workspace and organization labels, and the last ID-token verification time. Missing labels say the provider did not supply them. These claims describe the selected login, not every organization or workspace membership. They do not grant permission or prove a personal workspace. Reconnecting preserves the issued client ID, subject and workspace pins and keeps the current grant usable until successful verification. Automatic registrations treat email as verified metadata, so a refreshed email does not select another account. There is no account replacement or reset action. Confirmed deletion disconnects only the selected named setup connection.

The sealed pending intent records the existing registration fingerprint, including its absence. Completion checks it before code exchange and again in the atomic credential/registration/metadata write. A concurrent change to the same protocol registration rejects the connection and preserves the current grant. SIWC and Codex keep separate grants and account pins; either can reconnect while the other remains usable.

With both provider settings `auto`, the second choice calls `Credentials.startCodex("connect")`. It uses the existing encrypted device-auth implementation and the official `https://auth.openai.com/codex/device` page. The owner enters the displayed one-time code there. The browser polls only after the server's `nextCheckAt`, stops after the 15-minute attempt lifetime or a terminal failure, and cancels its timer when leaving the page. An authenticated reload recovers only the safe code, official verification link and timing. Device identifiers, tokens and verifier material stay encrypted in the DO. After rejecting HTML responses and Cloudflare challenges, this setup flow accepts an empty or whitespace-only 403/404 pending body without requiring a JSON content type. A nonempty body must be a bounded valid UTF-8 JSON object. The 403/404 status defines the pending response; no undocumented JSON error schema is inferred. Only explicit `access_denied`, `permission_denied` or `forbidden` error codes, literal plaintext access denials, HTML and Cloudflare challenges are classified as remote denials. Malformed or unknown non-JSON responses stop the attempt separately as invalid responses. Legacy image callers retain their original pending-response behavior. Remote availability still depends on OpenAI's service and account device-login settings.

Each successful completion atomically activates its own protocol and leaves the other grant unchanged. Starting, polling or failing never changes the active connection. Setup Codex registrations pin issuer, client, subject and account independently from SIWC, since SIWC need not return a ChatGPT account ID. The explicit setup intent can derive its initial email from a verified ID token; existing strict legacy Codex/image callers still require the configured email policy. There is no silent credential replacement or automatic cross-protocol fallback.

The protected `/account-info` POST reads Codex's selected-account and usage endpoints only for an already verified Codex grant. It projects supplied workspace name, plan and quota windows; it never returns other accounts or raw server responses. These are the Codex client backend endpoints, not a documented public SIWC usage API. HTTP denials or unsupported responses mark the information unavailable without disconnecting either grant, retrying or trying another route. An encrypted 60-second cache is scoped to the selected protocol, client, subject and account. A selection change during a lookup discards that lookup. The browser requests this snapshot once when opening a connected page or after completing a login, then on an explicit information refresh; device polling and status checks do not query usage repeatedly.

The authenticated same-origin `/gatekeeper/subscription/refresh` POST reuses the existing serialized OAuth refresh. A returned ID token must match the registered client, subject and workspace before replacing metadata. The UI distinguishes `updated` from `not_returned`; a token response without an ID token keeps the last verified metadata and its timestamp. SIWC does not provide a documented full subscription usage or remaining-quota API. The page marks that information unavailable and links to [ChatGPT usage settings](https://chatgpt.com/settings/usage). It never presents the Pi service's captured-token ledger as OS-wide or subscription-wide usage.

For OIDC OS login, copy `wrangler.oidc.example.jsonc` into private deployment configuration. Set `SUBSCRIPTION_AUTH_MODE=oidc` and bind `OS_SESSION` to the OS Workshop's named `SubscriptionSetupSession` entrypoint. Pin `SUBSCRIPTION_ADMIN_ISSUER`, `SUBSCRIPTION_ADMIN_SUBJECT` and `SUBSCRIPTION_ADMIN_EMAIL` to that administrator's exact verified OS identity. Every form HTML request and POST verifies the existing OS session through this private binding and compares all three pins before any Credentials call. Access headers and browser-supplied identity claims cannot authorize this mode. The verifier exposes no HTTP or public browser RPC route.

An anonymous OIDC GET returns a neutral bootstrap with no subscription forms or account data. It reads the OS's existing same-origin `localStorage.authToken` and requests the same page with `Authorization: Bearer`. Only a valid session matching all administrator pins receives the complete HTML. The authenticated document request carries the bootstrap's 32-character lowercase hexadecimal nonce in `x-subscription-document-nonce`, so its scripts and styles satisfy the original page's CSP. That header cannot authorize a request or choose an anonymous page's nonce. Access mode retains its JWT-protected document flow.

Missing or rejected OS sessions start native OIDC sign-in in the same tab at `/?sign_in=oidc&return_to=<encoded relative path>`. The return path is exactly `/gatekeeper/subscription`, optionally followed by `#add` or `#connection=owner` or a syntactically valid `account-<uuid>` connection hash. Unknown hashes are dropped; account membership is still checked by the authenticated catalog. A 401 clears only the stale `authToken` and any pending form, authorization link and device code. A 403 shows a fixed denial without restarting sign-in. The same behavior applies when a session stops authorizing requests in an already open form. API requests keep their JSON 401/403 responses.

The complete page reads the current OS token for each same-origin POST and keeps its forms disabled until authenticated status succeeds. The bootstrap and form send that token only in the Authorization header to this Worker's same-origin paths. They do not create another credential transport, write tokens to browser storage, display them or send them to OpenAI. Callback URLs are never stored. Old sessions without stored OIDC provenance must sign in again. This follows the OS session lifetime: sessions have no automatic expiry, and OS logout clears the browser token rather than revoking the server record. The verifier rejects unknown or deleted session records; it does not add IdP expiry checks or a revocation API.

For Access, copy `wrangler.example.jsonc` into private deployment configuration. Pin the Access issuer/audience and administrator email for Access mode. Keep OS origin, tenant, model and inference user list in the selected configuration. Supply a fresh 32-byte base64url `TOKEN_WRAPPING_KEY` through a Worker secret binding, and a stable instance-specific `TOKEN_WRAPPING_AAD`. Set both inference provider settings to `auto` to offer SIWC and Codex device login together, or keep both `siwc` for SIWC-only setup. The configured `INFERENCE_BRIDGE_ACCOUNT_ID` must stay `owner`; an authorized server request can explicitly select a known named connection with `subscriptionAccountId`. Omission keeps the configured owner behavior. The OS's private `CODEX_BRIDGE` service binding targets this Worker's `CloudAgentInference` entrypoint. No credential or model override comes from the browser. The protected `/select` POST accepts only `siwc` or `codex` and requires that connection to be ready; the server stores the active choice. A selected connection that becomes unavailable fails closed, without switching to the other grant.

## Local verification

Keep dependency installation outside the checkout. From this directory, use a unique temporary dependency directory and the public source repository:

```sh
subscription_deps=$(mktemp -d /tmp/subscription-deps-XXXXXX)
cp package.json "$subscription_deps/package.json"
npm install --prefix "$subscription_deps" --ignore-scripts --no-audit --no-fund
export SUBSCRIPTION_DEPENDENCIES="$subscription_deps/package.json"
export SUBSCRIPTION_SOURCE_ROOT=/path/to/public/allenlabs-cf-worker-apps
node check.mjs
node build.mjs /tmp/subscription-build/index.js
```

`build.mjs` resolves the public cross-app imports in a package-external stage, embeds SQL as text, then uses Wrangler's supported Workers conditions and Node compatibility bundler in dry-run mode. It never deploys. `check.mjs` drives actual Miniflare/workerd with generated Access/OpenAI keys and fully mocked outbound endpoints, plus the Korean form under jsdom. It checks owner plus two independently connected named objects, catalog exclusion and bounds, unknown selectors before object/network access, private explicit inference selection, rendered add/list/switch/delete confirmation and stale-response guards, connected and pending deletion, busy and Channel Talk reference guards, sibling/owner preservation, removed-account authorization and inference denial, Access and OIDC authorization before form HTML or any Credentials call, the no-form bootstrap, matching CSP nonces, same-tab sign-in and safe return hashes, stale-token removal and 403 denial, request bounds, automatic account discovery independent of the OS administrator, stale pre-login email policy, legacy identity policy, immutable account pins, stale and concurrent registration rejection, metadata refresh and missing claims, verified readiness, both protocol completion orders, selection, device interval/expiry/denial, private selected-transport inference, sanitized errors and the absence of callback/token persistence and logging. It neither contacts a live authorization service nor validates a real subscription. Generated bundles and synthetic fixture state stay in unique temporary directories.
