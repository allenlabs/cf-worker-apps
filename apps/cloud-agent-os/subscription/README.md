# ChatGPT subscription connections

This private Worker exposes the Korean connection page at `/gatekeeper/subscription`. Bind it to the existing OS router as `GATEKEEPER_SUBSCRIPTION`. The native router already forwards that path. Set `PUBLIC_ORIGIN` to the OS origin. With `SUBSCRIPTION_AUTH_MODE` omitted or set to `access`, protect the whole origin with the same Cloudflare Access application. This Worker separately verifies the Access JWT's signature, issuer, audience, expiry and its own pinned administrator email. It has no public route or inference HTTP endpoint.

Deploy it under a new Worker name with a new `Credentials` namespace. It re-exports the public Cloud Agent `Credentials` and `CloudAgentInference` implementations. The only DO binding and migration are `Credentials`. It never creates an Assistant, PiHarness or another agent loop. The imports include shared runtime dependencies; the selected connection methods only pin `TENANT_ID` and use DO storage. No D1, Channel Talk, SSO or GitHub binding is required.

The page asks for explicit subscription usage approval and calls `Credentials.start(true, "connect")`. The user selects an account and workspace at OpenAI without typing an email in the OS. A fresh namespace starts with `dynamic_agent_client`. Only an explicit setup intent can create a registration with `identitySelection: "oauth"`; its normalized email comes from a signature-, issuer-, audience-, expiry- and nonce-verified ID token. A pre-login email policy is neither enforced nor overwritten when no verified registration exists. Existing legacy registrations keep their email policy, and `start(true)` and Codex/image callers retain their strict behavior.

The official flow expects a local callback listener. This page uses the repository-tested manual adaptation: the user copies the full `http://127.0.0.1:1455/auth/callback?...` address into the page's form. Never ask for that address in chat. The form submits it only in a bounded same-origin JSON POST body and clears the field immediately. It does not navigate to, log or persist the callback URL in browser storage.

Readiness comes from `status.inferenceReady` for the selected protocol, with separate `siwcInferenceReady` and `codexInferenceReady` values. The protected page displays verified name, email, plan, supplied workspace and organization labels, and the last ID-token verification time. Missing labels say the provider did not supply them. These claims describe the selected login, not every organization or workspace membership. They do not grant permission or prove a personal workspace. Reconnecting preserves the issued client ID, subject and workspace pins and keeps the current grant usable until successful verification. Automatic registrations treat email as verified metadata, so a refreshed email does not select another account. There is no account replacement, reset or disconnect action.

The sealed pending intent records the existing registration fingerprint, including its absence. Completion checks it before code exchange and again in the atomic credential/registration/metadata write. A concurrent change to the same protocol registration rejects the connection and preserves the current grant. SIWC and Codex keep separate grants and account pins; either can reconnect while the other remains usable.

With both provider settings `auto`, the second choice calls `Credentials.startCodex("connect")`. It uses the existing encrypted device-auth implementation and the official `https://auth.openai.com/codex/device` page. The owner enters the displayed one-time code there. The browser polls only after the server's `nextCheckAt`, stops after the 15-minute attempt lifetime or a terminal failure, and cancels its timer when leaving the page. An authenticated reload recovers only the safe code, official verification link and timing. Device identifiers, tokens and verifier material stay encrypted in the DO. After rejecting HTML responses and Cloudflare challenges, this setup flow accepts an empty or whitespace-only 403/404 pending body without requiring a JSON content type. A nonempty body must be a bounded valid UTF-8 JSON object. The 403/404 status defines the pending response; no undocumented JSON error schema is inferred. Only explicit `access_denied`, `permission_denied` or `forbidden` error codes, literal plaintext access denials, HTML and Cloudflare challenges are classified as remote denials. Malformed or unknown non-JSON responses stop the attempt separately as invalid responses. Legacy image callers retain their original pending-response behavior. Remote availability still depends on OpenAI's service and account device-login settings.

Each successful completion atomically activates its own protocol and leaves the other grant unchanged. Starting, polling or failing never changes the active connection. Setup Codex registrations pin issuer, client, subject and account independently from SIWC, since SIWC need not return a ChatGPT account ID. The explicit setup intent can derive its initial email from a verified ID token; existing strict legacy Codex/image callers still require the configured email policy. There is no silent credential replacement or automatic cross-protocol fallback.

The protected `/account-info` POST reads Codex's selected-account and usage endpoints only for an already verified Codex grant. It projects supplied workspace name, plan and quota windows; it never returns other accounts or raw server responses. These are the Codex client backend endpoints, not a documented public SIWC usage API. HTTP denials or unsupported responses mark the information unavailable without disconnecting either grant, retrying or trying another route. An encrypted 60-second cache is scoped to the selected protocol, client, subject and account. A selection change during a lookup discards that lookup. The browser requests this snapshot once when opening a connected page or after completing a login, then on an explicit information refresh; device polling and status checks do not query usage repeatedly.

The authenticated same-origin `/gatekeeper/subscription/refresh` POST reuses the existing serialized OAuth refresh. A returned ID token must match the registered client, subject and workspace before replacing metadata. The UI distinguishes `updated` from `not_returned`; a token response without an ID token keeps the last verified metadata and its timestamp. SIWC does not provide a documented full subscription usage or remaining-quota API. The page marks that information unavailable and links to [ChatGPT usage settings](https://chatgpt.com/settings/usage). It never presents the Pi service's captured-token ledger as OS-wide or subscription-wide usage.

For OIDC OS login, copy `wrangler.oidc.example.jsonc` into private deployment configuration. Set `SUBSCRIPTION_AUTH_MODE=oidc` and bind `OS_SESSION` to the OS Workshop's named `SubscriptionSetupSession` entrypoint. Pin `SUBSCRIPTION_ADMIN_ISSUER`, `SUBSCRIPTION_ADMIN_SUBJECT` and `SUBSCRIPTION_ADMIN_EMAIL` to that administrator's exact verified OS identity. Every POST verifies the existing OS session through this private binding and compares all three pins before any Credentials call. Access headers and browser-supplied identity claims cannot authorize this mode. The verifier exposes no HTTP or public browser RPC route.

An OIDC GET serves a static shell without account data. The forms stay disabled until an authenticated status POST succeeds. The page reads the OS's existing same-origin `localStorage.authToken` for each POST and sends it only in the `Authorization: Bearer` header to this Worker's same-origin paths. It does not write browser storage, show the token or send it to OpenAI. Unauthorized requests disable the forms and show a fixed `/` OS sign-in link. Old sessions without stored OIDC provenance must sign in again. This follows the OS session lifetime: sessions have no automatic expiry, and OS logout clears the browser token rather than revoking the server record. The verifier rejects unknown or deleted session records; it does not add IdP expiry checks or a revocation API.

For Access, copy `wrangler.example.jsonc` into private deployment configuration. Pin the Access issuer/audience and administrator email for Access mode. Keep OS origin, tenant, model and inference user list in the selected configuration. Supply a fresh 32-byte base64url `TOKEN_WRAPPING_KEY` through a Worker secret binding, and a stable instance-specific `TOKEN_WRAPPING_AAD`. Set both inference provider settings to `auto` to offer SIWC and Codex device login together, or keep both `siwc` for SIWC-only setup. The account ID must stay `owner`. The OS's private `CODEX_BRIDGE` service binding targets this Worker's `CloudAgentInference` entrypoint. No credential or model override comes from the browser. The protected `/select` POST accepts only `siwc` or `codex` and requires that connection to be ready; the server stores the active choice. A selected connection that becomes unavailable fails closed, without switching to the other grant.

## Local verification

Keep dependency installation outside the checkout. From this directory, use a unique temporary dependency directory and the public source repository:

```sh
subscription_deps=$(mktemp -d /tmp/subscription-deps-XXXXXX)
cp package.json "$subscription_deps/package.json"
npm install --prefix "$subscription_deps" --ignore-scripts --no-audit --no-fund
export SUBSCRIPTION_DEPENDENCIES="$subscription_deps/package.json"
export SUBSCRIPTION_SOURCE_ROOT=/path/to/public/allenlabs-cf-worker-apps
node check.mjs
node build.mjs /tmp/subscription-build/index.js
```

`build.mjs` resolves the public cross-app imports in a package-external stage, embeds SQL as text, then uses Wrangler's supported Workers conditions and Node compatibility bundler in dry-run mode. It never deploys. `check.mjs` drives actual Miniflare/workerd with generated Access/OpenAI keys and fully mocked outbound endpoints, plus the Korean form under jsdom. It checks Access and OIDC authorization before any Credentials call, request bounds, automatic account discovery independent of the OS administrator, stale pre-login email policy, legacy identity policy, immutable account pins, stale and concurrent registration rejection, metadata refresh and missing claims, verified readiness, both protocol completion orders, selection, device interval/expiry/denial, private selected-transport inference, sanitized errors and the absence of callback/token persistence and logging. It neither contacts a live authorization service nor validates a real subscription. Generated bundles and synthetic fixture state stay in unique temporary directories.
